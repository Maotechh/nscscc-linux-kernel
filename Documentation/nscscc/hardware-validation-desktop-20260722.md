## Desktop image

The Buildroot image contains static LoongArch32 userspace for X.Org, fbdev,
evdev, Fluxbox, XTerm, eudev, and the NSCSCC framebuffer and NT35510 device.
The graphical session is a lightweight Fluxbox desktop, not GNOME. It is
intended to provide a usable X11 desktop on the experiment box without making
claims about GPU acceleration.

## Independent hardware runs

Both runs began with a fresh FPGA programming task. The Windows preflight
recorded interface index 3, link `Up` at 100 Mbps, host `10.90.50.43/24`, UDP
69 listening, one Tftpd32 process, and zero Vivado and SecureCRT processes.
Vivado 2023.2 returned exit `0`, reported startup `HIGH`, and reported the
expected `PROGRAMMED=` bitstream in both runs.

U-Boot used `10.90.50.44`, downloaded to `0xa3000000`, and used
`bootelf -p 0xa3000000 g console=ttyS0,115200 rdinit=/init loglevel=8`.
Each run transferred exactly 30595600 bytes and reported CRC32 `13433a3f`.
Tftpd32 recorded 0 resent blocks for both transfers.

The two status logs were accepted by `check-linux-runs.py` with
`result=success`. They record the Linux banner, 128 MiB physical memory,
exception and timer initialization, initramfs `/init`, `/ #`, build-info,
DMFE carrier and interrupts, zero network errors, three successful pings,
confreg reads and writes, and kernel error scans with no panic, Oops, BUG, or
call trace.

## Desktop and device checks

Both runs passed all of the following:

- `/dev/nt35510` exists and `dd if=/dev/zero of=/dev/nt35510 bs=768000 count=1`
  completed. BusyBox reported `1+0 records out`, which is the expected output
  for this device write.
- `/dev/fb0` exists, `/proc/fb` reports `nt35510`, virtual size is `480,800`,
  and bits per pixel is 16 (`FB0_RGB565_OK`).
- eudev, Xinit, X.Org, Fluxbox, and XTerm are running. Available memory after
  desktop startup was 52068 kB in run 1 and 53100 kB in run 2.
- The PS/2 controller at `1fe04000.ps2` probed and its Linux IRQ stayed at
  zero in both runs. No keyboard or mouse was attached, so key and pointer
  events were not tested.

The framebuffer and NT35510 writes prove the Linux device path and framebuffer
ABI. They do not prove that the physical LCD emitted visible pixels. The panel
was not directly observed during these runs, so `panel_status=not_observed`
remains the supported result.
